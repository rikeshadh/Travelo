Travelo Docker/API fix

Problem:
The production client was built with axios baseURL='' and served as static files by `serve`.
The Vite proxy in vite.config.js only works with `npm run dev`, so browser requests to /api/*
were sent to the frontend container instead of the backend.

Fix:
client/src/services/api.js now uses VITE_API_URL when provided.
client/Dockerfile accepts VITE_API_URL as a build argument.
docker-compose.yml builds the client with http://localhost:5000 for local Docker testing.

Local test:
  cd client
  docker rm -f travelo-client 2>NUL
  docker build --build-arg VITE_API_URL=http://localhost:5000 -t travelo-client .
  docker run -d --name travelo-client -p 3000:3000 travelo-client

  cd ..\server
  docker rm -f travelo-server 2>NUL
  docker build -t travelo-server .
  docker run -d --name travelo-server -p 5000:5000 travelo-server

Alternative with compose from Travelo root:
  docker compose down
  docker compose up -d --build

AWS:
Build the client with your deployed backend URL, e.g.
  docker build --build-arg VITE_API_URL=https://YOUR-BACKEND-DOMAIN -t travelo-client .

Do NOT use localhost as VITE_API_URL in AWS.
Do NOT publish server/.env with real secrets. Set PORT, MONGODB_URI, JWT_SECRET, etc. as ECS task environment/secrets.
